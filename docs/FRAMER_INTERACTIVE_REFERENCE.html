Connection and credential boundaries

The MCP entry is project-pinned. Use only the endpoint and authentication settings supplied through the project's trusted administrative channel. This public-safe reference intentionally omits live hostnames, project routes, IDs, credential schemes, and credential values. The Worker verifies that the resolved Framer project matches the selected project and has no cross-project fallback.

  • Never copy credentials into this file, prompts, tool arguments, URLs, source control, screenshots, or logs.
  • The Worker enforces its configured host allowlist; unapproved hosts or origins fail closed. Do not guess or add configuration values.
  • Use only read operations for connectivity checks. Do not test with a create, set, remove, merge, publish, or deploy call.
  • Framer permissions still apply, but the MCP tool list has no per-write confirmation gate.

Troubleshooting

Framer busy page

Upstream Framer availability/UI, not by itself an MCP authentication error. Treat a write's result as ambiguous, check current state with a read, and only retry after determining whether the first request took effect.

Request rejected before tools

Check the owner-provided project endpoint, required request headers, supported MCP protocol version, and that Upsy has the credential authorized for that same project. Do not expose the credential while diagnosing.

Framer operation failed.

The Worker redacts SDK exception details. Re-check the schema and target IDs, then use a safe read. Do not guess the hidden cause or repeat a write blindly.

Callback timeout

The callback did not arrive in 10 seconds. A subscription returns the first event, not a guaranteed initial snapshot; use a direct read where available.
